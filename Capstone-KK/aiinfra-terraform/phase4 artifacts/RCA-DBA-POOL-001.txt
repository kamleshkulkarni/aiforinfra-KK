=================================================================
3) ROOT CAUSE CONFIRMATION
=================================================================

Confirmed root cause:
Intentional reduction of PostgreSQL max_connections from 20 to 1 on vm-db,
followed by 5 concurrent pg_sleep(10) sessions, causing pool exhaustion.

Causal chain:
1. Configuration changed: max_connections 20 -> 1.
2. PostgreSQL restarted to apply the non-runtime parameter change.
3. Five concurrent connections started and consumed available capacity.
4. Additional client connection attempts would fail with too-many-clients
   behavior during the fault window.
5. Restoration reversed configuration and restarted service.

Contributing factors:
- max_connections requires restart to apply (operational disruption window).
- Single-instance lab design limits direct application-side telemetry.
- Azure Run Command output is coarse (success state, minimal stdout/stderr).
